Branch · jd-enhancer-ui

Guided JD Enhancement UX

Make the JD Enhancer's work visible: after research is confirmed, show the user the role they're applying for — its requirements (from the ad) plus a short synthesis of how their research shapes how they'd succeed — then let them confirm (and lightly edit) before gap analysis runs. No re-dump of the research already shown.

Frontend + server JD Enhancer v1.8 → v1.9 · KEMU upload + candidate_brief block No model swap · stays Flash 3.0
01

The problem

Today

JD Enhancer runs invisibly

After the research-confirm gate, the server fires the JD Enhancer as a background agent (runLinearDispatch → JD_ENHANCED) and immediately moves to the cover-letter prompt / gap analysis. The user never sees what the enhancement actually did — the work is abstracted away.

The gap

Today's JSON is built for the gap analysis, not the user

requirements.* stays cleanly ad-derived (good — the bubble labels it), but company_context just duplicates the research and role_details.overview is generic prose. Nothing is authored for the candidate. So the agent must emit a small new user-facing block — candidate_brief — that the bubble renders directly.

02

Flow change — insert a review gate

auto-advance

  1. research_pre_confirm → JD Enhancer (background)
  2. JD_ENHANCED fires → CL-prompt / gap analysis immediately
  3. User never reviews the enhanced JD

guided review

  1. JD Enhancer runs (unchanged)
  2. JD_ENHANCED → guided review bubble + gate, then STOP
  3. User reviews / edits requirements → jd_review_confirm
  4. Persist edits → proceed to CL-prompt / gap analysis (as today)

Implementation

Agent · JD Enhancer v1.8 → v1.9 · KEMU upload

New candidate_brief block — authored for the user

Add a Phase-5 block written for the candidate (plain, warm, 2nd person) that the bubble renders verbatim. Existing gap-analysis fields stay untouched → Analyst is unaffected, older runs degrade gracefully.

"candidate_brief": {
  "headline": "one warm line naming the role + what makes it tick",
  "role_in_context": "1-2 sentences: what this role really is, framed by research",
  "what_to_emphasise": ["angles/themes to foreground — NOT new requirements"],
  "requirement_notes": [{ "requirement": "<verbatim>", "why_it_matters": "one plain line" }]
}
  • Firewall still holds — what_to_emphasise are angles drawn from the hiring focus + JD duties, never new mandatory items.
  • No research re-dump — role_in_context references research as already-shown context; it doesn't re-list mission/culture.
  • Anti-fabrication — if research is INSUFFICIENT, the brief derives from the JD alone; never invent specifics. No internal terms ("firewall") in the copy.
  • De-code the instructions (your request) — convert the pseudocode-heavy phases to prose, like the 2026-06-19 de-constrain pass did for PB/HF/CLW/SC. Preserve as prose: the firewall, the statutory Mandatory-Requirements merge + dedupe, the Phase 6.0 keyword safety-net, the __DATE_TODAY__ + bare-filename rules. Schema stays literal (it's data).
  • Bump version → v1.9; update docs/CLAUDE.md + memory version tables.

05

Decisions, risks & verification

Decided

No redundancy with research

The earlier research card isn't re-rendered here. This view is about the role — requirements + a short synthesis of how research shaped it — with a link back to the research, not a repeat of it.

Decided

Editable requirements + caution

User can fix mis-read criteria; a caution banner warns that edits change gap-analysis input.

Watch

Redo dedupe + resume

Re-fired JD_ENHANCED must clear the 30s dedupe; reload at the gate must re-show (not skip) — both handled.

Verify end-to-end
  • node --check server files + npm --prefix client run build pass.
  • Upload v1.9 to KEMU; re-run the enhancer → enhanced_jd.json carries a populated candidate_brief (and unchanged requirements.*).
  • Fresh run → research confirm → bubble appears (no auto-advance); renders the brief + requirements; older run with no brief falls back cleanly.
  • Edit a requirement → continue → workspace/enhanced_jd.json reflects it AND gap analysis runs against the edited set.
  • "Re-read the job ad" re-runs the enhancer (no stall); reload at gate re-renders & still gates.
